# 検証ラン自体の生存確認 — 「遅い」と「止まっている」

## 問題の形

テストスイートをバックグラウンドで走らせて別の作業をする — エージェント開発では日常の光景である。そこにこの罠がある。

実例: フルスイートをバックグラウンドで起動し、**44 分間、出力ファイル 0 バイト・CPU 時間ほぼゼロ**のまま、「スイート待ちです、あと数分」と報告し続けた。オーナーの「そのシェル、進捗を把握できているの?」で確認したら、**遅いのではなくハング(永久停止)だった**。

> **既知の正常時間を大きく超える経過時間 + CPU ほぼゼロ = 「ブロックされている」仮説であって、「遅い」ではない。**

(このスイートの正常値は約 4.5 分。44 分・CPU 55 秒は「10 倍遅い」ではなく「何も実行していない」の形である。)

**読んでいないランの進捗を報告しない。**「もうすぐ終わります」と言ってよいのは、出力が伸びている・CPU を使っていることを確認したときだけ。これは[測定対象のずれ](measurement-target.ja.md)の時間版である — 「待っている」という行為が「検証が進んでいる」の証拠のような顔をする。

## 安全網 — ハングにスタックを吐かせる

ハングの最悪の性質は、**壁時計の時間を黙って食う**ことだ。Python/pytest なら faulthandler のタイムアウトを常備する:

```bash
pytest -o faulthandler_timeout=45   # 45秒止まったテストは全スレッドのスタックを出力して落ちる
```

これでハングは「無言の時間泥棒」から「**どのテストの・どのフレームで止まったかを自己申告する失敗**」に変わる。犯人探しは `-x`(最初の失敗で停止)で二分し、ダンプの最も内側のフレームが原因である。

## 実例の原因 — 非同期ワーカーの「不死身化」アンチパターン

このハングの原因は教育的なので、そのまま載せる。バックグラウンドで書き込みを排出し続けるワーカータスクがこう書かれていた:

```python
async def drainer(queue):
    while True:
        item = await queue.get()
        try:
            await write(item)
        except BaseException:   # ← ここが罠
            continue
```

Python の `asyncio` では、タスクの停止要求(キャンセル)は `CancelledError` **例外として**タスク内に届く。`except BaseException`(あるいは裸の `except:`)はこれを**飲み込んでしまう**。書き込みの最中にキャンセルが届くと、握り潰されてループが続行し、タスクは**不死身**になる。すると `asyncio.run` の終了処理(全タスクをキャンセルして待つ)が**永遠に待ち続ける** — これが 0 バイト・0 CPU の 44 分の正体である。

処方:

- **捕まえるのは `Exception` だけ**(本物の失敗は呼び出し元へルーティング)。
- **`CancelledError` は再送出する**(処理中の未完了応答があれば先に決着させてから)。これでタスクは停止要求どおり終了する。
- 終了処理の退行テストを書く: 終了処理をデーモンスレッド(プロセス終了を妨げない別スレッド)で走らせ、`join(timeout=...)` 後に**生きていないことを assert** する。退行したら CI がハングする代わりに**すぐ RED になる**。

## 実践方法

- [ ] バックグラウンドの検証ランに「正常ならこのくらい」の基準時間を持っているか
- [ ] 進捗を報告する前に、出力の伸びと CPU 使用を実際に見たか
- [ ] 長時間スイートに faulthandler タイムアウト(または相当の自己申告機構)を仕込んだか
- [ ] 新しく足した常駐ワーカー・排出タスクのキャンセル経路を監査したか(`except BaseException` / 裸 `except:` はないか)

## 出典(reyn 開発での実測)

#2259 PR-2a(2026-06-28): 44 分・0 バイト・CPU 55 秒を「遅い」と報告し続け、オーナー指摘で発覚。原因は排出ワーカーの `except BaseException` による `CancelledError` の握り潰し → 終了処理の永久待機。faulthandler ダンプが一次データとして原因行を特定した。
